# Folder Structure — where every file goes

## The rule

**A class's name ends in the name of the folder it's in.**

| Folder | Class names end in | Example |
|---|---|---|
| `Controllers/` | `Controller` | `ProductsController` |
| `Models/` | `Model` | `ProductModel`, `BookModel`, `ShoppingCartModel` |
| `Forms/` | `Form` | `AvatarUploadForm` |
| `Attributes/` | `Attribute` | `ValidatePermittedFileExtensionAttribute`, `RequireFeatureFlagAttribute` |
| `Events/` | `Event` | `AccountOpenedEvent` |
| `Exceptions/` | `Exception` | `InsufficientFundsException` |
| `Services/` | `Service` | `CategoryService`, `BankAccountService` |
| `Stores/` | `Store` | `ProductStore`, `UserStore` |
| `DbContexts/` | `DbContext` | `LibraryDbContext` |
| `Settings/` | `Settings` | `ShopSettings`, `EmailSettings` |
| `Constants/` | `Constants` | `FeatureNameConstants` |
| `Extensions/` | `Extensions` | `SessionJsonExtensions` |
| `Senders/` | `Sender` | `SmtpEmailSender`, `IEmailSender` |
| `Fakes/` | `Fake` | `AccountRepositoryFake` |
| `Fixtures/` | `Fixture` | `ProductCatalogWebsiteFixture` |
| a `...Tests` project | `Test` | `MoneyTest`, `BankAccountTest` |

The same goes for every other folder: `ModelBinders/` → `...ModelBinder`, `ViewComponents/` →
`...ViewComponent`, `Interceptors/` → `...Interceptor`, `HealthChecks/` → `...HealthCheck`,
`BackgroundServices/` → `...BackgroundService`, `Queues/` → `...Queue`, `Messages/` → `...Message`,
`Databases/` → `...Database`, `Factories/` → `...Factory`, `Repositories/` → `...Repository`,
`Dispatchers/` → `...Dispatcher`, `ValueObjects/` → `...ValueObject`, `Aggregates/` → `...Aggregate`,
`Generators/` → `...Generator`, `Shorteners/` → `...Shortener`, `Validators/` → `...Validator`,
`Middlewares/` → `...Middleware`, `Helpers/` → `...Helper`, `Endpoints/` → `...Endpoints`, `Hubs/` → `...Hub`,
`Clients/` → `...Client`, `Handlers/` → `...Handler`, `Requirements/` → `...Requirement`, `Seeders/` → `...Seeder`,
`DbContexts/` → `...DbContext`, `SerializerContexts/` → `...SerializerContext`, `Classifiers/` → `...Classifier`,
`Parsers/` → `...Parser`, `Outcomes/` → `...Outcome`, `Builders/` → `...Builder`, `Benchmarks/` → `...Benchmark`, `Senders/` → `...Sender`,
`Loaders/` → `...Loader`, `Evaluators/` → `...Evaluator`, `Strategies/` → `...Strategy`, `Commands/` → `...Command`,
`States/` → `...State`, `Contexts/` → `...Context`, `Mediators/` → `...Mediator`, `Requests/` → `...Request`,
`Results/` → `...Result`, `Observers/` → `...Observer`, `Publishers/` → `...Publisher`, `Pipelines/` → `...Pipeline`,
`Processors/` → `...Processor`, `Decorators/` → `...Decorator`, `Engines/` → `...Engine`, `Steps/` → `...Step`,
`Monitors/` → `...Monitor`, `ValueObjects/` → `...ValueObject`, `Jobs/` → `...Job`, `Notifiers/` → `...Notifier`,
`Readers/` → `...Reader`, `Collections/` → `...Collection`, `Enumerators/` → `...Enumerator`.

`Variations/` → `...Variation`: every project has one, holding **other ways to write the same code** for comparison
(see each README's **Variations** section). Two exceptions there: Razor Pages variations live in `Pages/Variations/`
and end in `PageModel`, and Blazor ones in `Components/Variations/` end in `Component` (framework naming).

Abstract base classes start with `Base` and still end in the folder name: `BaseOrderState` in `States/`,
`BaseApprovalHandler` in `Handlers/`, `BaseWorkflowStep` in `Steps/`.

Folder names are plural; the class name uses the singular (`Forms/` → `AvatarUploadForm`), except
where the class name itself is naturally plural (`ShopSettings`, `SessionJsonExtensions`,
`FeatureNameConstants`).

Interfaces follow the same rule after the `I`: `IEmailSender` is in `Senders/`.

## Also

- **One class per file, file named after the class:** `ProductModel` → `ProductModel.cs`.
- **The namespace matches the folder:** `Forms/AvatarUploadForm.cs` → `namespace FileUploadPortal.Forms;`.

## Why

You can tell what a class is from its name alone, and you know which folder to open to find it.
`DocumentUploadForm` → it's a form → it's in `Forms/`. Nothing has to be remembered or searched for.

## Exceptions

| What | Why |
|---|---|
| `Program.cs` | The app's starting point; every .NET project has one at the top level. |
| `Migrations/` | Generated by `dotnet ef migrations add`. Their class names are the migration names. Never edited by hand. |
| `Views/`, `wwwroot/` | Not C# classes: `.cshtml` pages and static files (CSS, uploads). |
| `Components/` (Blazor, 8.7) | `.razor` files, not `.cs`. `App.razor`, `Routes.razor`, `_Imports.razor` have framework-mandated names; pages end in `Page`, the reusable one in `Component`. |
| `Properties/launchSettings.json` | Not a class. Read by `dotnet run`: sets the URL and `ASPNETCORE_ENVIRONMENT=Development`, so `appsettings.Development.json` is loaded. |
| `Protos/` (gRPC, 8.9) | `.proto` contract files, not C# classes. |
| `Pages/` (Razor Pages, 8.6) | The framework requires each page's class (`*.cshtml.cs`) next to its `.cshtml`. Classes are named `...PageModel`. |
| Small console apps (1.1, 2.1, 5.1, 5.2, and 4.2's `Banking.Demo`) | Deliberately **one `Program.cs` file**, with their few classes at the bottom (a note at the top lists them). |

## Database table names

Renaming a class can rename its database table. Where a class has no `DbSet` property (6.1's
`AuthorProfileModel` and the book/tag join table, 6.2's `OrderLineModel`), the `DbContext` sets the
table name explicitly with `ToTable(...)`, so the database stays exactly as before.
